# 开发与本地验收报告

> 2026-10-22 更新：已接入微信读书公众号渠道，最新结果见 [微信读书接入验收](weread-validation.md)。下文为第一版交付时的历史快照。

日期：2026-10-21。版本：0.1.0。开发分支：`codex/2026-10-21`。

结论：第一版工程与本地模拟流程完成，可以启动工作台并进入真实账号验证。真实微信来源、Docker 镜像运行和长期采集稳定性尚未验收。

## 交付内容

- 独立 FastAPI 运行入口及 Vue/TypeScript 管理界面。
- SQLite WAL、固定 Alembic 基线、持久化任务、幂等写入、心跳与租约、单 Worker 和来源互斥。
- 公众平台扫码、公众号搜索、分页列表和正文适配器；凭据加密保存、限定 Cookie 域名、错误分类、不在频控后自动切换接口。
- 分离的正文补采、版本归档、可选图片任务；解析纯文本页面时明确图片状态未知。
- 查询、日期筛选、阅读、JSON/Markdown/RSS 文件、可撤销的只读 RSS 订阅链接。
- 来源暂停/恢复、任务取消/重试、站内异常合并提醒。
- 一致性备份、哈希校验恢复、每日自动备份及 7 日/4 周保留策略。
- 上游 SQLite 只读导入，已导入订阅默认暂停，不复制登录凭据。
- Docker Compose、锁定依赖、启动脚本、运维说明、自动化测试与浏览器验收脚本。

## 设计调整

原设计计划尽可能复用上游后台。代码检查发现原启动链含额外定时任务、自动回退以及打印凭据的路径，因此使用同一源码仓库中的独立运行入口、独立管理页面和无副作用的适配器，确保只通过新任务系统采集。旧后台未挂载到新服务。

新数据库与原 We-MP-RSS 数据库隔离；提供只读导入而不是直接修改未知旧库。UI/API 的变化以新运行说明为准。

## 尚未完成的外部验收与明确限制

1. 用户本人扫码及真实目标公众号验证尚未执行，需要 3～5 个目标及示例链接。
2. 尚未进行 7～14 天连续观察；来源完整性、发现延迟和人工干预频率没有实测结论。
3. Docker daemon 未启动，容器构建与容器内 Chromium 尚未验证。
4. 第一版仅启用公众平台来源；微信读书、多节点、AI、Word/PDF 不在默认运行路径。
5. 默认提醒为站内事件，外部通知渠道未接入。
6. 自动备份默认仍在本机；还需部署者指定其他挂载位置或同步到另一设备，才能覆盖整盘故障。
7. 浏览器渲染为可选能力；当前采集协议参考固定上游源码，接口若变化仍需维护。

目前不能承诺无账号限制风险、任意公众号完整历史或无需维护。

## 下一步操作

打开本地工作台，先创建管理员密码；进入“来源与授权”扫码。随后搜索并添加首批公众号，从“检查新文章”开始小规模验证，不先执行大范围历史回溯。

源码和运行说明均已保存在当前项目 outputs/we-mp-rss 中。尚未向任何远程仓库推送，也未对外发布服务。
